# Chrome Lens v1.1 - LLM Debugging Setup Guide

## Prerequisites

### Required Software

1. **Node.js 22.x** (LTS)
   ```bash
   nvm install 22
   nvm use 22
   node --version  # Should show v22.x.x
   ```

2. **Chrome/Chromium** (Latest stable)
   - Version 120+ recommended for full CDP support
   - Chrome Canary for experimental features

3. **Development Tools**
   - VS Code or preferred IDE
   - Chrome DevTools knowledge helpful

### Chrome Launch Configuration

For v1.1 debugging features, Chrome must be launched with additional flags:

```bash
# macOS/Linux
google-chrome \
  --remote-debugging-port=9222 \
  --user-data-dir=/tmp/chrome-debug \
  --enable-blink-features=DebuggerStatement \
  --js-flags="--expose-gc --max-old-space-size=4096" \
  --disable-features=BackForwardCache

# Windows
chrome.exe ^
  --remote-debugging-port=9222 ^
  --user-data-dir=C:\temp\chrome-debug ^
  --enable-blink-features=DebuggerStatement ^
  --js-flags="--expose-gc --max-old-space-size=4096" ^
  --disable-features=BackForwardCache
```

### Flag Explanations

- `--remote-debugging-port=9222`: Enable CDP connection
- `--enable-blink-features=DebuggerStatement`: Support debugger statements
- `--js-flags="--expose-gc"`: Enable memory analysis features
- `--max-old-space-size=4096`: Increase memory for large debugging sessions
- `--disable-features=BackForwardCache`: Ensure consistent debugging state

## Debugging Workflow Setup

### 1. Test Page Setup

Create a test page for debugging features:

```html
<!-- test/debug-page.html -->
<!DOCTYPE html>
<html>
<head>
  <title>Chrome Lens Debug Test</title>
</head>
<body>
  <h1>Debug Test Page</h1>
  <button id="errorBtn">Trigger Error</button>
  <button id="slowBtn">Slow Operation</button>
  
  <script>
    // Test error handling
    document.getElementById('errorBtn').onclick = () => {
      throw new Error('Test error for debugging');
    };
    
    // Test performance monitoring
    document.getElementById('slowBtn').onclick = () => {
      const start = Date.now();
      while (Date.now() - start < 1000) {
        // Simulate slow operation
      }
      console.log('Slow operation complete');
    };
    
    // Test state watching
    window.debugState = {
      counter: 0,
      data: []
    };
    
    setInterval(() => {
      window.debugState.counter++;
    }, 1000);
  </script>
</body>
</html>
```

### 2. VS Code Launch Configuration

Add to `.vscode/launch.json`:

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "node",
      "request": "launch",
      "name": "Debug Chrome Lens",
      "skipFiles": ["<node_internals>/**"],

      "env": {

    {
      "type": "chrome",

    }

  "compounds": [
    {
      "name": "Debug Full Stack",
      "configurations": ["Launch Test Page", "Debug Chrome Lens"],
      "stopAll": true
    }
  ]
}
```

## Verification Steps

### 1. Verify Chrome Connection

```bash
# Check Chrome debugging endpoint
curl http://localhost:9222/json/list

# Should return JSON with open tabs
```

### 2. Test Basic Debugging

```typescript
// Test script to verify debugging features
async function testDebugging() {
  // 1. Connect to Chrome
  await client.callTool('connect_to_chrome', {});
  
  // 2. List tabs
  const tabs = await client.callTool('list_tabs', {});
  console.log('Found tabs:', tabs);
  
  // 3. List source files
  const sources = await client.callTool('list_source_files', {
    tabId: tabs.tabs[0].id
  });
  console.log('Source files:', sources.files.length);
  
  // 4. Set a breakpoint
  const breakpoint = await client.callTool('manage_breakpoints', {
    tabId: tabs.tabs[0].id,
    operation: 'set',
    location: {
      url: sources.files[0].url,
      lineNumber: 10
    }
  });
  console.log('Breakpoint set:', breakpoint.breakpointId);
}
```

## Troubleshooting

### Common Issues

1. **"Cannot connect to Chrome"**
   - Ensure Chrome is running with debugging port
   - Check firewall settings
   - Verify port 9222 is not in use

2. **"Debugger domain not supported"**
   - Update Chrome to latest version
   - Check Chrome launch flags
   - Verify CDP connection

3. **"Source files not found"**
   - Ensure page is fully loaded
   - Check for source map issues
   - Verify file extensions filter

4. **"Breakpoint not hitting"**
   - Check source file URL matching
   - Verify line number validity
   - Ensure debugger is enabled

## Security Considerations

### Development Only

The v1.1 debugging features should **NEVER** be enabled in production:

```javascript
// Automatic disabling in production
if (process.env.NODE_ENV === 'production') {
  process.env.CODE_MODIFICATION_ENABLED = 'false';
  process.env.DEBUGGER_ENABLED = 'false';
}
```

### Access Control

Implement access control for debugging features:

```bash
# Restrict debugging to localhost only
DEBUGGING_ALLOWED_HOSTS=localhost,127.0.0.1

# Require authentication token
DEBUGGING_AUTH_TOKEN=your-secret-token
```

### Sensitive Data

Be aware that debugging tools can expose:
- Source code
- Environment variables
- User data
- Authentication tokens
- API keys

Always use separate development environments with test data.
